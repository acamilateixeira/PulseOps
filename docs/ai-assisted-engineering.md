# AI-assisted engineering

This log records where AI was used to build PulseOps, what was accepted or rejected, and how each result was checked. Responsibility for the code stays with the author, who reviews and merges every change.

## 2026-11-10 — Phase 1 foundation

- **Tool:** Claude (Opus 5.5), working in a sandbox without access to the npm registry.
- **Problem:** set up the monorepo, API, dashboard shell, database, Docker Compose and CI so that later phases build on tested ground.
- **What the AI did:** checked current package versions in the npm registry before choosing (Nest 12, Vite 8, Vitest 5, TypeScript 7 at the time); wrote the code, tests, ADRs and workflows.
- **Decisions taken from that check:** TypeScript pinned to 6.0 because `typescript-eslint` did not support 7 yet; API tests run on `tsc` output with `node:test` because esbuild-based runners do not emit the decorator metadata NestJS relies on.
- **Rejected:** a demo service with no behavior yet (would be scaffolding without function; it arrives in Phase 2 with telemetry); placeholder charts on the overview (the page states that telemetry is not collected yet).
- **Verification:** the contracts tests ran locally. Everything else is verified only by CI on the pull request, because the sandbox cannot install packages. The lockfile is generated by a workflow (`lockfile.yml`) running on GitHub, and the matrix status changes only after CI passes.
- **Limitations:** the code was written without a local type checker for NestJS and React; CI failures on the first runs are expected and fixed in follow-up commits, which this log records.

**Outcome:** the first CI run on the pull request passed all four jobs ([run](https://github.com/acamilateixeira/PulseOps/actions/runs/42892731758)): 21 tests, the full build, the Docker Compose smoke test through nginx and the dependency audit (one advisory below the `high` threshold, to review). No fix commits were needed for this phase.
